# toireshelter

仮タイトル **「Toiret」** — 一人暮らしのアパートの狭いユニットバスに閉じ込められ、室内の物を調べ、設備を動かして、自分の部屋へ帰る一人称3Dゲームの試作。

- エンジン：Godot 4 系（標準版・GDScript）
- Godot バージョン：**4.7.2 通常版**（project.godot は 4.7 として作成。4.4 以降なら動く想定）
- レンダラー：GL Compatibility（Mac / Windows で動きやすい軽量設定）
- 作り方：形は基本形状と軽量メッシュをコードで生成。表面の模様・ラベル・本の表紙・絵などは画像素材（ChatGPT の画像生成。一覧と加工は [docs/assets.md](docs/assets.md)）
- 外部の3Dモデル・プラグイン・購入素材：なし

## 起動方法

1. Godot を起動する（このMacでは `~/Downloads/Godot.app`。`/Applications` に移してもよい）。
2. プロジェクトマネージャーで「インポート」→ `toireshelter/project.godot` を選ぶ。
3. 開いたら **F5**（または右上の ▶ 「プロジェクトを実行」）。メインシーン `res://scenes/main.tscn` が起動する。
   - 古い/新しいバージョンで開くと「変換しますか？」と聞かれることがある。そのまま開いてよい。

## 遊び方（クリアまでの流れ）

1. 開始：ユニットバスの中。正面に浴槽、左に便器、右に洗面台と鏡裏収納、背後に入口ドア。
2. 設備は調べるだけでなく動かせる：便器の蓋・便座・タンクの蓋、水を流すレバー、浴槽と洗面台の蛇口と栓（水がたまり、栓を抜くと流れる）、浴室リモコン、鏡の扉、タオル、ペーパーホルダーのカバーなど。
3. **拾える物は3つ**：ドライバー（洗面台の下の床）、予備ロール（タンクの上の棚）、ユブロマン（同じ棚の入浴剤）。所持品欄は3枠。
   - ドライバー：ドアに F で使う。使っても減らない
   - 予備ロール：カバーを開けたペーパーホルダーに F で使うと交換され、消える
   - ユブロマン：水が10%以上たまった浴槽に F で使う。1回分で、使ったあとも空の容器が「ユブロマン（空）」として所持品に残る（もう一度使うと「もう空っぽだ。」）

**裏技ルート**：
1. 洗面台の下の床に**赤橙色の柄のドライバー**がある。見下ろして左クリックで取得 → 所持品欄に「ドライバー」。
2. ドアを調べる → 「ドアノブが空回りする。開かない。」（ドライバーを持っていれば「ネジがゆるんでいる」）
3. ドライバーを選んでドアを狙い、**F** → 修理してドアが外側へ開く（ドライバーは減らない）。
4. ドアの外の玄関ホールへ出る（自室へ入っても、ホールに出ただけでもクリアにならない）。ホールの左の壁の**玄関ドア（505）をクリックで開け**、外の共用廊下（5階）へ出ると「裏技ルートで脱出」。「もう一度」で最初から（すべて初期化）。

**正規ルート**：浴槽に入り（E）、天井の換気口を狙って「E：換気口へ入る」→ 低い姿勢で換気経路を這う（WASD）→ 角を2回曲がって外壁の出口で「E：ベランダへ降りる」→ ベランダの窓をクリックで開ける → 自室へ入り（ここではクリアしない）、玄関ホールの玄関ドアから廊下へ出ると「正規ルートで脱出」。換気経路の入口付近では「E：浴室へ戻る」。

### 設計メモ

- **空間の寸法と接続**（TASK-10。単位 m、x：右が＋、z：入口側が＋、y：上）
  - 浴室 x −0.9〜0.9, z −1.2〜1.2, 天井 2.2。換気口は天井の奥・左の隅（x −0.82〜−0.62, z −1.12〜−0.92 の穴）
  - 玄関ホール x −0.9〜0.9, z 1.3〜2.4（浴室のドアの外）。右の壁の出入口（z 1.5〜2.2）から自室へ
  - 自室 x 1.0〜4.0, z −1.2〜2.4, 天井 2.4（約3.0×3.6m）。浴室の右の壁を共有。奥の壁（外壁、z −1.3）に掃き出し窓（x 1.8〜3.2）
  - 換気経路（床 2.5、高さ 0.6。浴室と自室の天井の上）：入口の縦穴 → 横の管 x −0.95〜2.2（角1）→ 出口側の管 x 1.6〜2.2 で −z へ（角2）→ 外壁の出口（z −1.3、高さ 2.5〜3.1）。小さな換気口の奥が妙に広い
  - ベランダ x 1.3〜3.7（幅2.4）, z −2.1〜−1.3（奥行き0.8）, 床 0。換気経路の出口の真下（x 1.7）に着地し、すぐ右が窓。右端に室外機、窓の前にサンダル、左奥に植木鉢。手すりは腰板＋見えない壁で越えられない
  - 向かいのマンション：外壁の面 z −4.4（手すりから約2.3m）。背景だけ（くすんだ外壁・窓・配管・室外機・生活灯・電線）。上下の階のベランダも背景
- **クリア判定**（`main.gd`）：位置ではなく区画（浴室／ホール／自室／換気経路／ベランダ／廊下）の移り変わりで判定する。**玄関ホールから玄関ドアを抜けて廊下へ入った瞬間**にクリア。経路は、換気経路を通ってベランダへ降りたか（正規）、ドアを直して出たか（裏技）で決まる。2026-10-12 までは「自室に入った瞬間」だったが、「トイレから部屋に出ても脱出ではない／部屋から出たら脱出」に変更した。
- **ゴール（2026-10-12 決定、同日更新）**：脱出は**部屋から出たとき**（玄関ドアを開けて共用廊下へ）。浴室から自室・玄関ホールへ出ても脱出にならない。ここは5階の設定で、玄関ドアの外は他の部屋への通路（廊下）、エレベーターがあり、西側に下北沢（異世界）の街並みが見える。正規ルート＝換気口 → ベランダ → 窓から自室 → 玄関ドア。裏技ルート＝トイレのドアを直す → 玄関ホール → 玄関ドア。
- **見た目の方向性**：生活感のある普通のユニットバスに、少数のシュールな架空商品の名前や注意書きを混ぜる（謎解きの手掛かりはまだ入れない）。

- **見た目と当たり判定を分離**：各設備は `<設備名>/Visual`（見た目）と `<設備名>/Collision`（StaticBody3D、当たり判定＋調べる対象）に分かれている。GLB に差し替えるときは `Visual` の中身だけ入れ替えればよい（`room.gd` の `_build_toilet()` などを参照）。
- 当たり判定は壁・床・天井・各設備ごとの個別ボックス。部屋全体を覆う巨大な判定はない。
- 調べられる対象は `interact_id` メタデータで識別（`toilet` / `toilet_lid` / `toilet_seat` / `tank_lid` / `bathtub` / `bath_faucet` / `bath_plug` / `sink` / `sink_faucet` / `sink_plug` / `mirror_door` / `face_wash` / `toner` / `cotton_swabs` / `flush_lever` / `towel` / `towel_scratch` / `paper_cover` / `spare_roll` / `tub_note` / `shelf_note` / `tank_note` / `vent` / `vent_sticker` / `poster` / `bath_powder` / `paper_holder` / `spare_roll` / `toilet_cleaner` / `plunger` / `toilet_brush` / `driver` / `door`）。
- 照準判定はカメラからの RayCast。レイの最大長は 2.4m（`player.gd` の `INTERACT_RANGE_MAX`）、通常の対象の操作距離は当たり点まで 1.8m（`INTERACT_RANGE`）。メタデータ `interact_range` を持つ対象だけ個別の距離を使い、今は天井の換気口のみ 2.4m（`room.gd` の `VENT_RANGE`）。最初に当たった物で判定するので、壁・天井越しには操作できない。
  クリック時は `ray.force_raycast_update()` で今の視点からレイを撃ち直して判定する（`player.gd` の `try_interact()`）。画面の「左クリック：〜」表示は前回の物理フレームの結果を使うため、視点を素早く動かした直後は表示と実際の判定が一瞬ずれることがあるが、操作は常に今の視点で決まる。
- 壁パネルの継ぎ目・ゴム目地（`room.gd` の `_build_wall_details()`）は見た目だけで、当たり判定は従来の壁ボックスのまま。部屋の寸法からパネル幅約0.6mで等分して配置し、壁面から2mm浮かせてちらつきを防いでいる。
- 換気口（`Vent`）：`Vent/Visual/Frame`（枠）と `Vent/Visual/Cover`（暗い内部＋格子。原点が奥側の辺＝将来の蝶番）を分けてある。開閉は未実装。
- ドアの広告（`DoorPivot/Visual/Poster`）と入浴剤（`BathPowder`）：画像の仕様・取り込み設定・出典は [docs/assets.md](docs/assets.md)。広告の調べる判定はドアの判定の手前に重ねた薄い Area3D で、広告の外側はドアとして反応する。
- **状態を持つ設備**（TASK-05）は専用スクリプトに分けている：`toilet.gd`（蓋・便座の開閉）、`bathtub.gd`（くぼみ・水位・栓とチェーン・浴槽の蛇口）、`faucet.gd`（蛇口と水流。浴槽と洗面台で共用）。形状とマテリアルの共通処理は `mesh_kit.gd`。
  照準の判定に `fixture` メタ（設備ノード）があると、`main.gd` はその設備の `get_prompt(id)`（案内のキー）と `interact(id)`（説明文のキー、なければ空）に処理を任せる。文言はすべて `main.gd` の `PROMPTS`／`MESSAGES` にある。
- 便器：蓋（蝶番 x=-0.675, y=0.43、開き 88°）はタンクの手前、便座（蝶番 x=-0.645, y=0.40、開き 80°）は蓋の手前に立つので重ならない。蓋を閉じるとき便座が上がっていれば、先に便座を下ろしてから蓋を下ろす。アニメーション中（0.4秒）のクリックは無視する。
- 浴槽の水：水位 0〜1。蛇口が出ている間 +1/40 毎秒、栓が抜けている間 -1/25 毎秒（同時なら差）。満水の水面は y=0.50（縁は 0.55）。水面と水流はメッシュの位置・長さを変えるだけで、流体シミュレーションはしない。`bathtub.gd` の `advance(delta)` で時間を進められる（テストで使用）。
- 浴槽の排水口（栓とチェーン）は浴槽の水用、床の排水口（格子付き）は床に流れた水用で、今は見た目だけ。洗面台は TASK-07 から栓をすると水がたまり、栓を抜くと流れる（下の「洗面台」の項）。
- タオルの布地（繰り返し）と歯磨き粉のラベルは画像。仕様は [docs/assets.md](docs/assets.md)。
- 洗面台の下の排水管・トラップ、タオル、歯ブラシ類、床の排水口は見た目だけで、当たり判定はない（移動の邪魔にならない）。
- **トイレまわりの生活用品**（TASK-06、`supplies.gd`）：左の壁のペーパーホルダー（z=+0.30・高さ0.70）、タンクの上の壁の棚（上面1.35m）に包装された予備ロールと洗剤、手前左の床の隅にラバーカップとトイレブラシの収納台、換気口の横に点検シール。すべて調べられる。予備ロールは TASK-09 から取得できる（ほかは取得できない）。点検シールの操作距離は換気口と同じ 2.4m。収納台だけ体がめり込まないよう単純な箱の当たり判定を付け、調べる判定はそれより少し大きくしてある。
- **貯水タンク**（TASK-07、`toilet.gd`）：本体は中空で、中に水面・ボールタップ（給水管と浮き玉）・オーバーフロー管・排水弁（黒いゴム弁）・レバーの腕とチェーン、外に壁からの給水管と止水栓。陶器の蓋は蝶番を使わず、持ち上げる → 浴槽側へずらす → 立てる → 向きを変える → タンクと浴槽の間の壁際に下ろす（約1.3秒）。この経路は上の棚・入浴剤・開いた便器の蓋と便座・ホルダーと重ならないことを、テストで毎フレーム確認している。入浴剤はタンクの上から上の棚へ移した。
- **洗面台**（TASK-07、`sink.gd`）：ボウルにくぼみ・排水口・ゴム栓。水位は浴槽と同じ流量差の計算で、満水まで 12 秒、満水から空まで 8 秒。満水の水面はボウルの縁より 2cm 下。初期状態は蛇口OFF・水量0・栓あり。
- **鏡裏収納**（TASK-07、`mirror_cabinet.gd`。TASK-08 で壁へ埋め込み）：収納箱（奥行き 0.10m、高さ 1.28〜1.78m、棚2段）。鏡の扉は浴槽側の縁の蝶番で部屋側へ 100° 開く。中に化粧水・洗顔料・綿棒（単色の仮デザイン）。閉じた扉と収納箱の板が、中の物への照準を遮る。扉とタンクの蓋にはぶつかる判定がなく、移動を妨げない。
- **姿勢**（TASK-08、`player.gd` の `pose`）：WALK（立つ）／CROUCH（しゃがむ：C、目 0.6m・体 0.7m・速さ 0.8m/s）／SEATED（便器に座る：E）／IN_TUB（浴槽の中：E）／TRANSITION（座る・入る・出るの 0.6 秒の移動演出）。一度に一つだけで、操作が混ざらない。立ち上がるときは立った体が入る空間を `is_space_free()` で確かめ、狭ければ立たない（洗面台の下など）。座る／浴槽では決まった位置から見回すだけで、体の当たり判定と重力を切る。戻る先は通路側の候補から最初に空いている所（`main.gd` の `SEAT_EXITS` / `TUB_EXITS`）。座っている間は蓋と便座を開閉できない。
- **トイレを流す**（TASK-08、`toilet.gd` の `flush()`）：タンク正面のレバー（`flush_lever`）をクリック。約4.7秒でレバー・排水弁・タンクの水位と浮き玉・便器の水と渦が動いて元に戻る。流している間のクリックは無視。**音は未実装**（使える音素材がないため）。
- **照明**（TASK-08）：電球色の天井灯（弱め）と暖色の環境光、Filmic のトーンマッピングで白い設備の白飛びを抑える。床は淡いグレージュ（壁より少し暗く、彩度が低い）。
- **鏡裏収納の埋め込み**（TASK-08）：収納箱は右の壁の厚み（x 0.9〜1.0）の中。右の壁は開口を空けて4枚に分けてある。閉じた鏡面は壁面から約2mm手前。開口の前面に「体だけを止める」透明な板（物理レイヤー5）を置き、照準のレイは通す。
- **持ち物**（TASK-09／TASK-11、`main.gd`）：拾えるのはドライバー・予備ロール・ユブロマンの3つ（所持品欄は3枠、1〜3キー）。同じ物は重複して取れない。F は選んだ物を照準の対象に使い、成功したときだけ消費する（ドライバーは消費しない）。一時停止中・移動演出中は使えない。Q の拡大表示は、拾ったときに複製した3Dモデルを別の3D空間（SubViewport）で回して見せる。
- **ペーパーホルダー**（TASK-09、`supplies.gd`）：初期状態は芯だけ・カバー閉。カバーはクリックで開閉（蝶番）。カバーが開いていて予備ロールを選んでいるとき F で交換：芯を外して収納台の脇の小皿に置き、新しい白いロールを付ける（0.6秒、連打しても二重消費なし）。カバーが閉じていれば「先にカバーを開けよう。」で、消費しない。
- **タオル**（TASK-09、`towel.gd`）：クリックでバーの上を入口側へずれ（たぐり寄せた形）、裏の壁の引っかき傷が見える。照準の判定は、ずらし終わってから寄せた位置へ、戻すときは動き始めに元へ移すので、タオルが覆っている間は傷を調べられない。所持品にはしない。
- **隠し場所**（TASK-09）：姿勢で表示を切り替えず、実際の位置と遮蔽物で見え方を作っている。テストで通路の立ち位置14か所から見えないことを確認。
  - 浴槽の手前の縁の裏の紙（`bathtub.gd`）：内側を向いていて縁に遮られる。浴槽に入ると読める。満水の水面より上
  - タオルの裏の傷（`towel.gd`）：タオルをずらすと見える
  - 棚板の裏の紙（`supplies.gd`）：棚板に当たり判定を付けて上から遮る。座る・しゃがむと目線が棚板より下になり、見上げると読める
  - タンクの真下の壁の紙（`supplies.gd`）：立つとタンク、正面からは便器に遮られる。しゃがんで通路から覗くと読める（便器の蓋が開いていると入口寄りからだけ）
  - 紙は仮の無地（影でも紙と分かるよう弱く自己発光）。謎の進行には結び付けていない
